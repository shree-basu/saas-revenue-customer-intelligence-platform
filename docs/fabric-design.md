# Fabric integration — source-controlled, inert design

`fabric/pipelines/FinanceTargets.DataPipeline` uses Microsoft's published DataPipeline item file names and v2 `.platform` metadata shape. Its only activity is an active `Fail` gate. It has **no** Copy activity, schedule, trigger, connection reference, credential or valid cloud source/sink. It cannot ingest data. The companion `fabric/contracts/finance-targets.json` defines the future finance-target business key, schema, immutable batch controls, idempotent upsert and reconciliation obligations. Local CI checks that these artifacts remain inert.

The real production implementation would require a separately approved Fabric workspace/capacity, an authorized Microsoft-side source connection, an Azure-hosted Snowflake destination connection supported by Fabric, secure secret handling outside Git, a Copy activity, staging/validation, a failed-batch path, and source-to-target reconciliation before publication. None exists here, and adding them can incur charges. An operator must never import or run these artifacts as if they were a complete ingest pipeline.

This shape follows Microsoft's [DataPipeline definition](https://learn.microsoft.com/en-us/rest/api/fabric/articles/item-management/definitions/datapipeline-definition), [Git source format](https://learn.microsoft.com/en-us/fabric/cicd/git-integration/source-code-format), and [Snowflake copy-activity requirements](https://learn.microsoft.com/en-us/fabric/data-factory/connector-snowflake-copy-activity). Offline structural validation does not prove Fabric accepts or executes this definition.
